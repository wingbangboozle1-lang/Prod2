# archive/ is not part of the published site

These are previous builds of the same project, kept for the record. **None of them is a
publication.** The canonical site is the repository root (and `docs/`), generated by
`tools/build.py`.

Why this note exists: GitHub Pages serves this repository in legacy "main /" mode, so every
file committed to the root — including every `.html` in this directory — is fetchable by anyone
at `https://wingbangboozle1-lang.github.io/Prod2/archive/…`. `robots.txt` asks crawlers not to
index it, but robots.txt is a request, not an access control, and it does nothing about the
duplicate-content problem: still-live copies of pages that exist in the canonical site compete
with the canonical site in search results.

## What changed on 2026-11-20

`tools/build.py` now writes a `noindex` directive into **every** `.html` and `.xml` file under
`archive/` on each build:

```html
<meta name="robots" content="noindex, nofollow">
```

plus a matching `X-Robots-Tag`-equivalent comment for XML. `tools/checks.py` (section
`integrity`) fails the build if any archived page is missing it, so the guard cannot rot.

`robots.txt` also now disallows the whole archived surface, including the variants that were
never listed before.

## What this does NOT fix

A `noindex` is honoured by well-behaved crawlers and is the strongest signal a static host can
give. It is **not** an access control: a human with the URL, or a scraper that ignores meta
robots, can still read these files. Removing them from the host is an owner action, and it is
recorded as **F-P19 / F-P20** with the exact setting to change (Settings → Pages → Source:
GitHub Actions, which serves `docs/` only).

The build also deletes the served copies rather than only tagging them where it can: see
`tools/build.py` → `main()`, which rewrites these files in place each pass.
