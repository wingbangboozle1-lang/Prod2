Confirmation workflow before any product CTA

  1. Identify the intended product and confirm its ASIN using an official Amazon product page or an authorized Associates tool.
  2. Save the official listing URL, confirmation date, source, and reviewer for that intent record.
  3. In the enrolled Associates workflow, test one Special Link per product. Verify its destination and confirm the click appears in the authorized tracking report.
  4. Record any observed redirect target in its own field. Never overwrite the intended ASIN or official listing URL with a redirect observation.
  5. Only after review, publish a clearly labeled product link with rel="sponsored" and the disclosure visible on the page. Recheck links periodically.

Official review references: Amazon Associates Operating Agreement · Amazon Associates Program Policies · FTC Disclosures 101 · Google guidance on qualifying outbound links.

Events to instrument after a privacy and policy review

  • page_view — page path and timestamp only; no full IP address or cross-site identifier.
  • guide_open — guide slug from an internal navigation action.
  • outbound_click — approved destination class and link record ID; never record query strings or personal data.
  • disclosure_view — page where the disclosure appears, for validating placement.
  • purchase_report_import — aggregate value entered only from an authorized Associates report; no individual-level data.

These are a proposed event schema, not events currently collected. A static site cannot provide a self-hosted analytics endpoint by itself; a reviewed, deployed server component and retention/access policy would be required. Do not automate Amazon data collection or scraping.
