## 4. Findability — what this pass changed (X-01)

The live host is legacy Pages serving `main /`, so `docs/` (a byte-identical second copy of the
site), `site/` (the preserved older build), `content/`, `data/`, `tools/`, `archive/` (122 files
of old builds) and the root `.md` files are all fetchable at their URLs. The brief's bar is
"**one site to index**". Status after this pass:

1. **Canonicals** (primary control): every published page's canonical points at its own root URL;
   `site/`'s pages canonicalize to the current pages; `docs/` is exact-duplicate content that
   canonicals resolve. Verified (rule F, 30/30).
2. **Crawl policy** (changed this pass): `robots.txt` (root mirror and `docs/`) now disallows
   `/Prod2/docs/`, `/site/`, `/content/`, `/data/`, `/tools/`, `/scripts/`, `/tests/`, `/var/`,
   `/npm/`, `/.arena-import/`, `/*.md$`, `server.mjs`, `analytics-client.js`, `package.json`,
   `.gitignore`, `.nojekyll` — in addition to the existing `/Prod2/archive/` rule. Generated by
   `tools/build.py::build_robots()`; consistency gated in `scripts/verify_site.py` (rule J).
3. **Sitemap**: lists exactly the 30 published root pages, nothing under any source tree (rule J).
4. **Irregularity flagged (new, see F-P25 proposal)**: on `*.github.io` project sites the
   robots.txt crawlers must read by spec is the **host-root** file
   (`https://wingbangboozle1-lang.github.io/robots.txt`), which belongs to the account's user
   site, not to `/Prod2/robots.txt`. The disallow list above is therefore best-effort for
   compliant crawlers; the canonicals and Search Console (SG-29, owner action) are the controls
   that will actually collapse duplicates. Manual review link:
   https://developers.google.com/search/docs/crawling-indexing/robots/robots-txt ("must be
   placed at the top-level directory of the site").
5. **Owner action (unchanged, F-P19/F-P20/SG-46)**: switch Pages to *GitHub Actions* so only the
   `docs/` artifact is served and the source tree disappears from the web. Attempted via the API
   this pass (`PUT /repos/{owner}/{repo}/pages {"build_type":"workflow"}`) → **HTTP 403**
   ("Resource not accessible by integration"), confirming the sandbox token cannot do it.
   Exact owner steps: repository **Settings → Pages → Build and deployment → Source: GitHub
   Actions**. The deploy workflow (`.github/workflows/pages.yml`) is already correct and uploads
   `docs/` as the artifact.
