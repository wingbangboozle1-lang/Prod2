What this publication is

Prod2 is a reader-facing static publication about air fryers and kitchen thermometers. It puts product comparisons and question-led buying and usage guides first, and keeps the research trail — method, flagged items, open questions, suggestions, decisions, compliance and measurement — reachable from one navigation group and every footer. Product details come from the source records in this repository and carry their verification dates and limits; anything unconfirmed stays blank or flagged rather than filled in.

A product listing is not a hands-on test. A listed capacity or a listed dimension does not by itself establish serving size, whether a real piece of food will fit, how fast a machine cooks, how popular it is, or that one product is better than another. Where the site compares two products, it compares the values that were actually read, and it names the trade-off instead of declaring a winner (D-23).

Every outbound Amazon product link is a tagged Special Link marked rel="sponsored", and each page carries the Associates disclosure directly beneath the masthead with a repeat in the footer. The owner-supplied short links are kept in intent records beside any redirect observation; this summary does not declare them compliant or non-compliant. The campaign ledger is empty by rule: a local click count is not an order, a commission or a revenue record.

What is deliberately absent

  • Prices and star ratings — withheld by policy, not by oversight (F-02, D-P11).
  • Hands-on testing claims — nobody here has cooked with these machines, so the site is a specification publication until real usage exists (D-06, queued as SG-07).
  • Forecasts and conversion scores — the campaign ledger starts empty and fills only from authorized first-party reports.
  • Popularity claims — a "best" or "most popular" statement needs a dated official snapshot, which the site does not have (D-19).

Measurement: five local events, two deployment roles

The browser client (assets/js/measure.js) declares exactly five local events — page_view, outbound_click, guide_read_75, category_click, feed_click — and carries no visitor identity: no cookies, no identifiers, no referrer capture, and only the ASIN and target host on an outbound click. While settings.analytics_endpoint is empty, nothing leaves the browser; events are counted in the reader's own local storage, for the reader's own view.

The two deployment roles are different things and are not interchangeable:

  • Static publication (what is live). GitHub Pages serves files. It exposes no API, so the live site collects nothing and the configured endpoint attribute is deliberately empty. The client can emit events; nothing is receiving them.
  • Optional self-hosted endpoint (not hosted). server.mjs is a dependency-free Node server that accepts the same five events over POST /api/events, validates each body against the published contract, and stores daily aggregate counts per event and path in a single JSON file. It stores no IP address, user agent, referrer, cookie, timestamp or visitor identifier, and writes no request log. It is deployable on any owner-controlled host; it is not deployed (F-19, Q-23).

The campaign ledger's five events (impression, click, session, order, refund) are a third, separate, report-only system (D-P05). A ledger row appears only when the owner exports an authorized report.

AI answer platforms: a measurement question, not an optimisation target

Google's own guidance, read on 2026-11-20, sets the boundary. There are no additional technical requirements to appear as a supporting link in AI Overviews or AI Mode: a page must be indexed and eligible for a snippet, which is the same requirement as ordinary Search. The generative AI features retrieve from the Search index with query fan-out, so eligibility follows ordinary indexing rather than a separate application. A site must be included in Search generative AI features in Search Console to be eligible for display, and AI-feature traffic is reported only inside the "Web" search type of the Performance report — so AI visibility cannot be separated out at all until the property is verified, which it is not.

Two further constraints shape the roadmap. Producing content for every query variation, including fan-out queries, violates Google's scaled content abuse spam policy, so this site's fourteen-day editorial cadence stands and no query-farmed pages are written. And Google's documented lever is non-commodity content: for this site that means the dated verification register and its published limits — not first-hand reviews, which nobody here can honestly write.

The evidence-gated roadmap is published as SG-42, with the two missing inputs recorded as Q-P15 and Q-P16 and the stance as D-P16. No llms.txt, no AI-only structured data and no machine-generated summaries of listings are added: the guidance documents no such requirement, and Amazon listing photography stays unpublished until the Program Content licence review closes (Q-P05).

What the local gates prove, and what they cannot prove

python3 tools/build.py && python3 tools/checks.py renders the publication and runs the release gate over the result: unique titles and meta descriptions, disclosure placement, the Amazon link policy, internal link integrity, markup validity, register cross-references, sourced product facts, banned claims, site chrome, SEO metadata, sitemap and feed coverage, the shop shelf, publication consistency and build freshness. npm test adds the endpoint's own contract test.

Passing those gates proves that the code and the repository data meet those checks on the commit that was checked. It does not prove live deployment success, legal approval, search visibility, affiliate acceptance, sales or revenue. Live deployment was confirmed separately for this review: the repository's Pages API reported the site built and serving from branch main at the repository root, and the published sitemap, feed and robots file were fetched successfully.

Open items for a decision-maker

  1. Run the one-link-per-product test in Associates Central — it gates every attribution claim (F-57, F-58, Q-01).
  2. Host the endpoint and verify the property in Search Console — everything downstream depends on it (SG-06, SG-29, F-P13, Q-P08).
  3. Settle the reader-capture consent basis before the question form is connected (Q-47, F-P14).
  4. Decide whether to adopt a dated-snapshot price policy, and only with automation (SG-05).
  5. Decide the product-photography question; Amazon listing photography is Program Content (D-12, D-22).
